# コメントの整理

AGENTS.md の「コメント (`///` を含む) は、なぜ別の書き方をしないかを言うためだけに書く」を、リポジトリの全 `.cs` で守れる状態にするための基準と手順 (#936)。
この作業に限り、AGENTS.md の「既存コメントは、その説明するコードを変えない限り残す」は適用しない。

対象は `.cs` のコメント (`//`, `///`, `/* */`) だけ。`Tooltip` などの文字列、`#region` / `#pragma` の行、`.sh` / `.props` のコメントは対象外。

## 判定の基準

コメントの塊ごとに `keep` / `delete` / `rewrite` のどれかにする。

| 判定 | 当てはまるもの |
| --- | --- |
| `keep` (残す) | なぜ別の書き方をしないかの理由だけを書いたもの。順序の制約、素直な書き方だと壊れる理由、意図的に外している理由、一見不要に見える処理が要る理由など。すでに `//` で書かれているときだけ (`///` なら `rewrite`) |
| `delete` (消す) | 何をするか・何であるかの説明、引数・戻り値・例外の説明、使い方や実行コマンド (`<code>unity -batchmode ...</code>` など)、区切り (`// ----`)、TODO、コメントアウトされたコード |
| `rewrite` (書き換える) | 説明と理由が混ざったもの。理由の部分だけを残す。理由が `///` や XML タグで書かれているものも、`//` の文にする |

ツールが読むコメント (`// <auto-generated>`、`// ReSharper disable ...`、`// @formatter:off`、`// language=...`) は残す。`comments-extract` はこれを出さないので判定は要らない。

### 書き換えた後の形

- 理由は `//` で書く。`///`、`<summary>` などの XML タグ、`<see cref="..."/>`、`<c>...</c>` は使わず、識別子名をそのまま書く (`TriggerSpec.FireInterval` のように)。最後の issue で lint が `.cs` 内の `///` をエラーにする。
- 「〜するため」「〜すると〜になるので」のように、別の書き方を選ばない理由が読めるようにする。コードを読めばわかる「何をするか」は前置きとしても足さない。
- 書き換え後の本文は `comments-apply` が元の字下げの `// ` の行にするので、判定には記号を付けない本文だけを書く。

### 迷いそうな例

説明と理由が混ざった `<summary>` → 理由だけを `rewrite` で残す。

```csharp
/// <summary>
/// 予備弾を pool から出し入れするようにする。pool に既にある分は数えて足りない分だけ移す。
/// 作り直した武器 (持ち替えや拾い直しで同じ弾数のまま作る) が弾を増やさないようにするため。
/// </summary>
```

```csharp
// pool に既にある分は数えて足りない分だけ移すのは、作り直した武器 (持ち替えや拾い直しで同じ弾数のまま作る) が弾を増やさないようにするため。
```

`<param>` / `<returns>` に理由が 1 つだけ入っている → その理由だけを残し、引数の説明は消す。

```csharp
/// <param name="thickness">測り切れなかった厚さは float.PositiveInfinity で渡す。0 にすると貫通したことになってしまうため。</param>
```

```csharp
// 測り切れなかった厚さを 0 でなく float.PositiveInfinity で渡すのは、0 だと貫通したことになってしまうため。
```

`<code>` の実行手順 → `delete`。手順はタスクの description や docs が持つ。

```csharp
/// <summary>サーバーのデータを書き出す。</summary>
/// <code>unity -batchmode -quit -projectPath . -executeMethod Shooter.Editor.MapCollisionExporter.Export</code>
```

順序の制約を書いた `//` → 理由なので `keep`。

```csharp
// 静的フィールドは書いた順に初期化されるので、Default より先に置く。
private static readonly float[] _defaultFieldOfViews = { AdsZoom.DefaultFieldOfView };
```

何をするかを書いた `//` → `delete`。直後の行を読めばわかる。

```csharp
// 弾を 1 発減らす
_rounds--;
```

結果だけを書いた `//` で、その結果を選んだ理由がコードから読めないもの → 理由がわかる形に `rewrite`。理由がわからなければ、推測で書かずに `delete` する。

```csharp
// 押し続けたまま持ち替えたり生き返ったりしても、押し直すまで止めない。
```

`<inheritdoc/>` や中身の無い `<summary>` → `delete`。

## スクリプト

`scripts/comments.py` (Python 3、標準ライブラリだけ) を make のタスクとして呼ぶ。make に渡す引数のうち `-` で始まるものは make に食われるので `ARGS="..."` で渡す。

### `make comments-extract <パス>...`

指定したファイル・ディレクトリ以下の `.cs` (`bin` / `obj` / `.git` は除く) から、コメントの塊を 1 行 1 件の JSONL で出す。ファイル全体を読まずに判定するために使う。`ARGS="--out <ファイル>"` でファイルに書く。

```json
{"id": "Assets/game/Scripts/Core/Weapons/AimSpec.cs:10:9#1a2b3c4d", "file": "Assets/game/Scripts/Core/Weapons/AimSpec.cs", "start": 10, "end": 10, "kind": "block", "text": "// 静的フィールドは書いた順に初期化されるので、Default より先に置く。", "next": ["private static readonly float[] _defaultFieldOfViews = { AdsZoom.DefaultFieldOfView };", "private static readonly IReadOnlyList<float> _defaultZoomLevels = Array.AsReadOnly(_defaultFieldOfViews);", "public static readonly AimSpec Default = new AimSpec();"]}
```

- `id`: `<ファイル>:<開始行>:<開始列>#<本文のハッシュ>`。判定ではこれだけを写す。
- `kind`: `block` はコメントだけの行が続いた塊 (空行で切れる)。`inline` はコードと同じ行にあるコメント 1 つで、`code` にその行のコードが入る。
- `text`: 本文 (各行の字下げを落としたもの)。
- `next`: 直後の、空行でもコメントだけの行でもない行を 3 行まで。

### `make comments-apply <判定の JSONL>`

判定を 1 行 1 件で書いたファイルを反映する。

```json
{"id": "Assets/game/Scripts/Core/Weapons/AimSpec.cs:10:9#1a2b3c4d", "action": "keep"}
{"id": "Assets/game/Scripts/Core/Weapons/BreathHold.cs:98:9#5e6f7a8b", "action": "delete"}
{"id": "Assets/game/Scripts/Core/Weapons/Ammo/MagazineAmmo.cs:124:9#9c0d1e2f", "action": "rewrite", "rewrite": "pool に既にある分は数えて足りない分だけ移すのは、作り直した武器が弾を増やさないようにするため。"}
```

- `delete`: 塊の行を消す。消した跡で空行が 2 行以上続けば 1 行にし、`{` の直後・`}` の直前・ファイルの先頭と末尾に残った空行は消す。`inline` はコメントだけを消してコードの行は残す。
- `rewrite`: `rewrite` の本文 (改行で複数行) を、元の字下げの `// ` の行にする。`inline` のコメントは消して、その文の上の行に置く。本文に `//` などの記号や XML タグがあればエラーにする。
- `keep`: 何もしない。判定を残しておくために書く。
- ファイルの中身が抽出のときと違う件 (行がずれた、本文が変わった) や、id が重複した件はエラーとして行を出し、その件だけ飛ばして他は反映する。エラーが 1 件でもあれば 1 で終わる。飛ばした件は、そのファイルを `comments-extract` し直して判定し直す。

### `make comments-verify [<基準 ref>]`

基準 (既定 `main`、無ければ `origin/main`) と HEAD の分岐点から作業ツリーまでの `.cs` の変更が、コメントと空白・空行だけであることを確かめる。コメントと空白を除いたトークン (文字列・文字のリテラルは中の空白ごと 1 つ) を比べ、違えば次のように行を出して 1 で終わる。`.cs` 以外のファイルの変更は見ない。

```
Assets/game/Scripts/Core/Weapons/AimSpec.cs:8 (main): - public const float DefaultRecoilRecoveryDelaySeconds = 0.15f;
Assets/game/Scripts/Core/Weapons/AimSpec.cs:8: + public const float DefaultRecoilRecoveryDelaySeconds = 0.2f;
```

### `make comments-test`

`scripts/tests/test_comments.py` を走らせる。

## 手順

issue ごとに、割り当てられた範囲のファイルだけを扱う。判定ファイルは git が無視する `Temp/comments/` に置く。

1. 抽出する。
   ```sh
   make comments-extract Assets/TutorialInfo ARGS="--out Temp/comments/tutorial.jsonl"
   ```
   出力が大きければディレクトリやファイルを分けて抽出する。
2. 各件の `text` と `next` (`inline` なら `code` も) だけを読み、上の基準で判定して `Temp/comments/tutorial.judgments.jsonl` に `id` と `action` (と `rewrite`) を書く。ファイル全体は読まない。判定に迷う件だけ、その行の前後を読む。
3. 書き戻す。
   ```sh
   make comments-apply Temp/comments/tutorial.judgments.jsonl
   ```
   エラーの件があれば、そのファイルを抽出し直して 2 からやり直す。
4. コメント以外を変えていないことを確かめる。
   ```sh
   make comments-verify
   ```
5. `git diff` で、消した・書き換えたコメントと、詰めた空行を見る。

### 試した結果 (`Assets/TutorialInfo/**/*.cs`)

`Readme.cs` にはコメントが無く、`Editor/ReadmeEditor.cs` の 3 件はどれもそこのコードが何かを書いた見出しなので `delete` にした。

| 本文 | 判定 | 理由 |
| --- | --- | --- |
| `//Remove ImGUI` | `delete` | 直後の 2 つの空の override が何をしているかの説明 |
| `//Header` | `delete` | 区切り |
| `//Content` | `delete` | 区切り |

どれも前に空行が 1 行あり後ろがコードなので、消した跡の空行は 1 行のまま残る。
