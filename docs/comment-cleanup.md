# コメントの整理 (#936)

`.cs` のコメントを、AGENTS.md の「なぜ別の書き方をしないか」だけにする作業の基準と手順。

## 判定の基準

コメントの塊ごとに、次のどれかに決める。

| 判定 | 当てはまるもの |
|---|---|
| keep | なぜ別の書き方をしないかの理由。素直な書き方だと壊れる・遅い・ずれる理由、順序の制約、意図的に外している・二重にしている理由、外部 (Unity・EOS・C# 9) の制約。 |
| delete | 何をするか・何であるかの説明 (`<summary>`、`<param>`、`<returns>`、`<exception>`、`<value>`)、名前や型を言い直しただけの文、使い方や実行コマンド (`<code>unity -batchmode ...</code>`)、区切りや見出し (`//Header`)、TODO。 |
| rewrite | 説明と理由が混ざっている塊。理由の部分だけを `//` の文にする。`///` の塊で残すべき理由があるものもここ。 |

- 理由は `//` で書く。`///`・XML タグ・`<see cref="X"/>` は使わず、識別子名 `X` をそのまま書く。
- コードを読めばわかる理由 (「null なら返す」など) は理由ではなく説明として消す。
- 迷ったら、そのコメントを消したときに次に読む人が「なぜこう書かないのか」と書き直してしまうかで決める。書き直されそうなら残す。
- ツールが読むコメント (`// <auto-generated>`、`// ReSharper ...`、`// @formatter:`、`// language=`) と `#pragma` は抽出に出ないので、そのまま残る。

### 例

```csharp
/// <summary>拾われた物。<see cref="Pickup.DestroyOnCollect"/> なら受け取った後に破棄される。</summary>
public Pickup Collected { get; }
```

説明だけなので delete。

```csharp
// 静的フィールドは書いた順に初期化されるので、Default より先に置く。
private static readonly float[] _defaultFieldOfViews = { AdsZoom.DefaultFieldOfView };
```

順序の制約なので keep。

```csharp
/// <summary>
/// 今のプロフィールのレベルで id が使えるか。<see cref="Recorder"/> が無ければ全部使える。
/// 述語として渡す先が呼ぶたびに今のプロフィールを引くので、試合中にレベルが上がればその場で使えるようになる。
/// </summary>
```

1 行目は説明、2 行目は値を覚えずに毎回引く理由なので rewrite し、`// 値を覚えずに呼ぶたびに今のプロフィールを引くのは、試合中にレベルが上がればその場で使えるようにするため。` にする。

## 手順

ファイル全体は読まない。判断に周りのコードが要る塊だけ、その行の前後を読む。

1. 塊を抜き出す。

   ```sh
   mkdir -p Temp/comments
   make comments-extract Assets/game/Scripts/Runtime/Mode > Temp/comments/mode.txt
   ```

   各塊は次の形で出る。行末コメント (`inline`) は、その行だけが出る。

   ```text
   @@ Assets/game/Scripts/Core/Weapons/AimSpec.cs:10-10:746b97dc block
           // 静的フィールドは書いた順に初期化されるので、Default より先に置く。
   -- next
           private static readonly float[] _defaultFieldOfViews = { AdsZoom.DefaultFieldOfView };
   ```

2. 判定ファイル (`Temp/` の下に置く。git は無視する) を書く。1 行に id と判定を書き、rewrite は続く行に新しい本文を書いて `@@end` で閉じる。本文に `//` は付けなくてよい (付けても外す)。字下げは元の塊に揃う。行末コメントの rewrite は、その行の上に `//` の行として置かれる。

   ```text
   Assets/game/Scripts/Core/Weapons/AimSpec.cs:10-10:746b97dc keep
   Assets/game/Scripts/Core/Weapons/Ammo/HeatAmmo.cs:28-28:231d2551 delete
   Assets/game/Scripts/Core/Progression.cs:40-43:0a1b2c3d rewrite
   値を覚えずに呼ぶたびに今のプロフィールを引くのは、試合中にレベルが上がればその場で使えるようにするため。
   @@end
   ```

   keep は書かなくても残る。

3. 書き戻す。

   ```sh
   make comments-apply Temp/comments/mode-decisions.txt
   ```

   抽出の後でファイルが変わった塊は id が合わず、`differs from the extracted one` のエラーになって残る。その塊はもう一度抜き出して判定する。消した塊の後の空行は、2 行続く・`{` の直後・`}` の直前にならないよう詰める。

4. 確かめる。

   ```sh
   make comments-verify
   make lint
   ```

   `comments-verify` は main との分岐点からの `.cs` の差分に、コメントと空行以外の変更が無いことを見る。`<see cref>` を消したことで使われなくなった `using` は lint が IDE0005 で止めるので消してよく、verify もその削除だけは通す。

量が多いときは、ディレクトリやファイルの区切りごとに 1〜4 を繰り返す。
